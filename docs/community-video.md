# 커뮤니티 동영상 업로드

운동법 작성 화면에서는 동영상만 선택할 수 있습니다. 파일의 MIME 유형과 영상 트랙을 확인한 뒤, 첫 장면을 썸네일 미리보기로 표시합니다. 미리보기 아래의 시간 조절 바를 움직이면 선택한 시각에 가장 가까운 장면을 불러옵니다. 선택 시각과 전체 영상 길이를 함께 표시하며, 현재 미리보기의 장면이 게시글 썸네일로 저장됩니다.

장면 추출은 백그라운드 스레드에서 처리하고 긴 변이 최대 720픽셀인 JPEG로 변환합니다. 바를 빠르게 움직이면 마지막 요청 위치를 우선 반영하며, 새 장면을 불러오는 동안 등록을 막아 이전 썸네일이 저장되지 않도록 합니다. 사진을 별도로 선택하는 기능은 제공하지 않습니다.

동영상의 기본 길이 메타데이터가 없거나 0이면 영상 트랙의 길이를 확인합니다. 트랙에도 길이가 없으면 실제 영상 샘플의 시각을 읽어 타임라인 길이를 구합니다. 이 확인도 백그라운드에서 처리합니다.

기본 길이 메타데이터가 없는 영상은 장면 탐색도 잘못될 수 있어, 앱 캐시에 시간 정보를 보완한 임시 MP4를 만듭니다. 재인코딩하지 않고 영상·오디오 샘플을 복사하므로 원본 파일은 변경하지 않습니다. 썸네일은 임시 파일에서 추출하고 업로드에는 원본 동영상을 사용합니다. 임시 파일은 영상 교체 또는 작성 화면 종료 시 삭제를 시도합니다.

## 저장 구조

동영상과 썸네일을 Firebase Storage에 모두 업로드한 다음 Firestore에 게시글을 저장합니다.

- `posts/{uid}/{postId}/video`: 원본 동영상. 원래 MIME 유형을 유지합니다.
- `posts/{uid}/{postId}/thumbnail.jpg`: 사용자가 선택한 장면에서 생성한 JPEG 썸네일입니다.
- Firestore의 `posts/{postId}`: 기존 게시글 필드에 `videoPath`, `thumbnailPath`를 함께 저장합니다. 두 필드에는 Storage 파일 경로가 들어갑니다.

피드와 작성자 프로필은 공통 게시글 어댑터를 사용합니다. 어댑터에서 썸네일 다운로드 주소를 조회하고 Glide로 이미지를 불러오고 캐시합니다. 미디어가 없는 기존 게시글에는 기본 이미지를 표시합니다.

피드 카드는 썸네일이 3:4 비율의 카드 전체를 채우고, 운동 부위·제목·반응 수를 반투명 배경 위에 겹쳐 표시합니다. 좋아요는 하트, 댓글 수는 말풍선, 별점은 노란 별 아이콘으로 표시합니다. 댓글 수는 `commentCount`를 읽으며 기존 문서에 필드가 없으면 0으로 표시합니다. 댓글 작성이나 좋아요 변경 기능을 추가한 것은 아닙니다.

상세 화면에서는 Firebase Storage의 동영상 주소를 조회해 Media3 플레이어로 재생합니다. 재생·일시정지·시간 이동이 가능하며, 화면을 벗어나면 플레이어를 해제합니다. 화면 회전이나 복귀 시 재생 위치를 복원합니다. 영상이 없는 기존 게시글에는 안내를 표시하고, 주소 조회나 재생 실패 시 다시 시도 버튼을 표시합니다.

기존에 업로드한 영상의 길이가 0으로 읽히면 해당 영상만 앱 캐시에 내려받아 시간 정보를 보완한 뒤 재생합니다. 서버의 원본은 변경하지 않습니다. 이 경우 처음 재생 준비에 다운로드 시간이 필요하며, 작성자 프로필로 이동했다 돌아오거나 화면을 회전하면 준비한 파일을 재사용합니다. 상세 화면을 완전히 종료하면 임시 파일을 정리합니다.

## Firebase 설정

1. `app/google-services.json`에 설정된 Firebase 프로젝트에서 Cloud Storage를 활성화합니다.
2. 채팅으로 안내한 동영상·썸네일 접근 규칙을 Firebase 콘솔의 Storage 규칙에 적용하고 게시합니다. 규칙은 별도 파일로 관리하지 않습니다. 다른 기능에서 사용하는 기존 규칙은 유지해야 합니다.
3. Firestore 규칙에서 로그인한 작성자가 문자열 형태의 미디어 경로를 포함한 게시글을 생성할 수 있도록 허용되어 있는지 확인합니다.

4. Firestore의 복합 색인에서 `posts` 컬렉션의 `status` 오름차순·`createdAt` 내림차순 색인과 `authorId` 오름차순·`status` 오름차순·`createdAt` 내림차순 색인을 확인합니다. 둘 다 쿼리 범위는 컬렉션이며, 이미 있다면 추가하지 않습니다.

이번 앱 코드 변경만으로 서버에 배포된 규칙이나 색인이 변경되지는 않습니다. 설정은 Firebase 콘솔에서 직접 적용합니다.

## 직접 확인할 항목

1. 로그인한 뒤 커뮤니티에서 운동법 작성 화면을 엽니다.
2. 동영상만 선택할 수 있는지, 선택을 취소하면 이전 선택이 유지되는지, 동영상 없이 등록할 수 없는지 확인합니다.
3. 재생 가능한 동영상을 선택하고 시간 조절 바를 처음·중간·끝으로 움직여 미리보기와 시각 표시를 확인합니다. 빠르게 여러 번 움직인 뒤 마지막으로 고른 장면이 반영되는지도 확인합니다. 세로 동영상도 확인합니다.
4. 필수 항목을 입력하고 등록합니다. 업로드 진행률이 표시되고 등록 버튼과 동영상 선택 버튼이 비활성화되는지 확인합니다.
5. 장면 선택 또는 업로드 도중 화면을 회전합니다. 선택한 시각과 썸네일이 유지되고 진행 중인 작업이 중복 실행되지 않는지 확인합니다.
6. Storage에 파일 두 개가, Firestore에 게시글 문서 한 개가 저장되었는지 확인합니다. 피드와 작성자 프로필에서 썸네일을 확인하고, 목록을 스크롤해 카드가 화면 밖으로 나갔다 돌아와도 올바른 이미지가 표시되는지 확인합니다.
7. 읽을 수 없는 동영상이나 Storage 접근 권한이 거부되는 상황을 확인합니다. 미디어 업로드에 실패하면 게시글이 등록되지 않고 다시 시도할 수 있어야 합니다.
8. 게시글 상세에서 재생·일시정지·시간 이동을 확인합니다. 작성자 프로필로 이동하거나 앱을 백그라운드로 보내면 소리가 멈추고, 돌아왔을 때 재생 위치가 복원되는지 확인합니다.
9. 피드의 썸네일이 카드 아래쪽까지 채워지는지, 제목과 아이콘의 숫자가 밝은 이미지에서도 읽히는지 확인합니다. 영상 없는 기존 게시글도 확인합니다.

## 현재 동작과 제한 사항

- 화면 회전 등으로 화면이 다시 생성되어도 업로드 상태는 유지됩니다. 다만 앱 프로세스가 종료된 뒤에는 진행 중이던 업로드가 자동으로 재개되지 않습니다.
- 미디어 업로드에 실패하면 일부만 업로드된 파일의 삭제를 시도합니다. 네트워크나 권한 문제로 삭제가 실패할 수 있습니다.
- Firestore 저장에 실패한 경우에는 서버의 실제 저장 결과가 불확실할 수 있으므로 업로드된 미디어를 유지합니다. 게시글에 연결되지 않은 파일을 정리하는 기능은 추후 서버에 추가할 수 있습니다.
- Storage의 MIME 규칙은 파일 메타데이터를 검사합니다. 실제 파일 내부의 영상 데이터까지 검사하는 규칙은 아닙니다.
